プライバシー / セキュリティ / AIコーディング / データ漏洩 — 2026-11-15

Lovableアプリが
旅券情報と20万件のDMを露出

AIコーディングプラットフォーム「Lovable」で構築されたアプリが、ユーザーのパスポート詳細情報と20万件超のプライベートメッセージを含む機密データを外部から参照可能な状態で漏洩させていたとセキュリティ研究者が報告した。509ポイント・184コメントと今日最大の反響。バイブコーディングツールが生み出すコードのセキュリティ問題が改めて浮き彫りになった。
何が漏れていたか
旅券情報・DMが認証なしで参照可能
APIエンドポイントが認証チェックなしでアクセス可能な状態だったことが判明。影響を受けたアプリは少なくとも数十件。SupabaseのRow Level Security（RLS）設定が自動生成コードで省略されたことが主因とみられる。
Lovableとは
コードを書かずにウェブアプリを作るAIツール
プロンプトからReact+Supabaseのフルスタックアプリを自動生成するサービス。Supabase連携でバックエンドも自動構成されるが、設定ミスが直接データベースへのアクセス権限に繋がるリスクがある。
HNコメントの洞察
「バイブコーディングのセキュリティ問題の縮図」
184コメントの多くが「AIが生成したコードのセキュリティレビューは人間が必ず行うべき」と指摘。「これはLovableだけの問題ではなく、全てのAIコーディングツールに共通する構造的リスク」という意見が上位に。

プライバシー / EFF / テクノロジー政策 / データ権利 — 2026-11-15

テック企業が「プライバシー」の
概念を書き換えようとしている——EFF

EFF（電子フロンティア財団）が、テクノロジー企業が再び「プライバシー」という概念そのものを再定義しようとしていると警告する記事を公開した。405ポイント・152コメント。「データを匿名化すれば問題ない」「サービス改善のためのデータ利用は社会的利益」という論理で、個人がデータをコントロールできるという従来のプライバシー概念を骨抜きにしようとする動きが業界全体で起きているという。
何が変わろうとしているか
従来のプライバシー概念：個人が自分のデータの収集・利用・共有を制御できる権利。企業が推し進めようとしている新解釈：「匿名化されたデータは個人情報ではない」「AI学習への利用はオプトアウト不可の標準設定」「データは共有することで社会的価値が生まれる」という枠組みへの転換。
EFFが具体的に指摘する動き
AI学習データへのオプトアウト機能の削除・難化、匿名化データの再識別リスクを無視した政策立案ロビー活動、プライバシー保護法のザル化を目指す業界団体の動き。これらが同時多発的に起きており、「再定義」が意図的な戦略として進められているとEFFは主張する。
HNでの議論の焦点
「これは2000年代のクッキー同意問題の繰り返し」という見方と「今回はAIが絡むため影響が桁違い」という警戒感が交錯。「EFFは重要な問題を提起しているが解決策が弱い」という建設的批判も。法規制と技術的プライバシー保護（差分プライバシー等）の組み合わせが必要との意見が支持を集めた。

ハードウェア / 開発ツール / Android / SBC — 2026-11-15

高価なPiを買う理由はない
——古いスマホがあるなら

古いスマートフォンをRaspberry Piの代替として活用する方法を詳述した記事が473ポイント・268コメントを集めた。中古Androidは数千円で入手でき、内蔵Wi-Fi・Bluetooth・GPS・カメラを標準装備しながら優秀なSBCとして機能する。Pi不足と価格高騰が続く中、「手元にある古いスマホ」が最高のシングルボードコンピュータになる可能性を実例と共に示した。
古いスマホがSBCとして優れている理由
① コスト：Pi 5が1万円超に対し、中古Android（Galaxy S8、Pixel 3など）は数千円。② 内蔵センサー：カメラ・GPS・加速度計・気圧計・NFCが最初から付いている。③ バッテリー内蔵：停電対策不要のUPS機能つき。④ ディスプレイ付き：ステータス表示のための追加ハード不要。⑤ Termux：フルLinux環境がAndroid上で動く。
具体的なユースケース
家庭内サーバー（Termux + nginx）、GPIO相当のことはUSB OTGで対応、カメラを使った監視カメラ（IP Webcam）、Home Assistantのサテライトデバイス、Pythonスクリプト実行環境。著者はGalaxy S7をずっと使っており「Piより安くて速い」と主張。
HNコメントで挙がった制限
「GPIOが必要な電子工作にはやはりPi」「長期間の常時起動でバッテリー膨張リスク」「メーカーのセキュリティサポート終了問題」という現実的な指摘も多数。しかし「サーバー用途に限定すれば非常に実用的」という結論が大勢。ハードウェアリサイクルの視点でも評価された。

宇宙 / SpaceX / 再利用ロケット / エンジニアリング — 2026-11-15

SpaceX、Starship第15回飛行で
Mechazillaキャッチ再び成功

SpaceXがStarshipの第15回飛行試験を実施し、ブースター（Super Heavy）の「Mechazilla」機械アームによるキャッチに成功した。297ポイント・155コメント。前回Flight 14に続く2回連続キャッチ成功で、完全再利用ロケットの実用化に向けた重要なマイルストーン。上段（Starship本体）の制御再突入と太平洋への精度着水にも成功し、将来の完全再利用システム確立に向け着実に前進した。
Mechazillaキャッチとは
発射台「Mechazilla」（本名: Starbase）の巨大な機械アームがブースターを空中でキャッチするシステム。高さ約71mのブースターが精密に位置を合わせながら降下し、アームが約20秒で挟み込む。成功すれば着地脚不要→重量削減→コスト低減に繋がる。Flight 14が世界初成功（2024年10月）から2回連続で成功した。
今回の成果と次のステップ
ブースターキャッチ成功に加え、Starship本体が大気圏再突入後にインド洋に高精度で着水。次のマイルストーンはStarship本体の「Mechazilla」キャッチとされており、両段を完全再利用するシステムの完成が近づいている。NASAのアルテミス計画で月面着陸機として採用予定のため、開発加速の重要性が高い。
HNコメントの反応
「毎回これを見ると感動する」という反応が多い一方、「本当に重要なのはこれがどれだけ早く再飛行できるかだ」というコスト・ターンアラウンドへの関心も高い。SpaceXがFlight 14ブースターをFlight 15でも再使用したかどうかへの質問が多く、答えはNoで今回は新しいブースターだった。

プライバシー / 規制 / EU / Meta — 2026-11-15

イタリア、MetaにAndroidユーザー
データ問題で887億円の制裁

イタリア競争・市場・消費者局（AGCM）がMetaに対し8億8700万ドル（約1300億円）の制裁金を科したとReutersが報じた。285ポイント・193コメント。Androidユーザーのデータへのアクセス方法がEUの競争法に違反するとの判断。Metaは反論しているが、EUにおける規制圧力はプラットフォーム企業への大型制裁が相次いでいる。
何が問題だったか
MetaがAndroidユーザーのデバイスデータ・行動データにアクセスする手法が、競争上の優位性を不当に強化していると判断された。具体的には、Metaアプリが他のAndroidアプリのデータにも広範にアクセスし、広告ターゲティングに活用していた点が問題視された。GDPRとEU競争法の双方の観点から審査されていた。
EUでの規制の潮流
今年だけでMetaはアイルランド・フランス・ドイツでも制裁を受けており、EUでの累積制裁額は数十億ドルに達している。DMA（デジタル市場法）施行後、GatekeeperとしてのMetaへの規制執行が加速。HNコメント: 「罰金の金額はMetaの四半期利益の一部にすぎない——ビジネスコストとして計算されているのでは」という懐疑的意見も。
日本への示唆
EU型の強力なプラットフォーム規制の流れは日本にも影響している。個人情報保護委員会が2026年にプラットフォーム事業者への立ち入り検査権限を強化したばかりで、類似の調査が日本でも始まる可能性がある。HNコメントでは「米国でこれが起きていないのは規制当局の問題」という指摘が多数。

AI / 環境 / 言語的不公平 / トークナイゼーション — 2026-11-15

生成AIは英語以外のテキストに
著しく多くのエネルギーを消費する

ミシガン大学の研究チームが、生成AIは英語以外のテキスト処理に著しく多くのエネルギーを消費することを明らかにした。160ポイント・89コメント。原因はトークナイゼーションの効率差——英語は1単語が平均1〜2トークンで済むのに対し、日本語・アラビア語・ヒンディー語などは同じ情報量を表現するために3〜10倍以上のトークンが必要で、計算量とエネルギー消費が比例して増大する。
なぜトークン数が違うのか
GPT系モデルが使うBPE（Byte Pair Encoding）トークナイザーは英語テキストで最適化されている。英語の「hello」は1トークン。日本語の「こんにちは」は文字ごとに分解され5〜7トークンになることも。アラビア語・タイ語なども同様に非効率で、同じ意味の文章でも言語によってトークン数が数倍変わる。
定量的な差
研究によると日本語プロンプトは同等の英語プロンプトに比べ平均3.4倍のトークンを消費。アラビア語では2.8倍、ヒンディー語では4.1倍。エネルギー消費はトークン数にほぼ比例するため、非英語話者は同じ情報処理で数倍のカーボンフットプリントを負担している計算になる。
解決策としての多言語トークナイザー
GoogleのGemmaや日本語特化モデルは多言語最適化トークナイザーを採用しており差を縮めている。HNコメント: 「これはエネルギー問題であると同時に、非英語話者がAIを使う際のコスト不公平問題でもある」。多言語対応の改善は環境・公平性両面での重要課題として認識が広まりつつある。

開発ツール / Python / セキュリティ / パッケージ管理 — 2026-11-15

PyPI、プロジェクトページを刷新
——セキュリティシグナルが一目で分かる

Pythonパッケージ配布インフラ「PyPI」がプロジェクトページのデザインを刷新し、セキュリティ情報をより見やすく表示するUI更新が完了したとPyPIブログが発表した。176ポイント・81コメント。2FA認証の有無・Sigstoreによる署名状態・クリティカルプロジェクトフラグなどのセキュリティ情報が一目で確認できるようになり、悪意あるパッケージの見分けやすさが向上した。
具体的に何が変わったか
① セキュリティバッジエリアを新設：2FA有効・Sigstore署名・OIDC発行者情報をページ上部に集約。② アクティビティグラフ改善：最新リリースのタイムラインが見やすくなり、長期放置パッケージの判断が容易に。③ サプライチェーン情報：ソースコードへのリンクとファイルハッシュ（SHA256）の表示を強化。PyPIの悪意パッケージ問題への継続的な対策の一環。
HNコメントの評価
「セキュリティ情報が見やすくなるのは歓迎」という反応が多い。一方で「見た目よりも、タイポスクワッティング対策や自動悪意検知の強化のほうが重要では」という本質的な問題提起も。「npmのほうが先にこういった取り組みをしていたが、PyPIも追いついてきた」という比較コメントも。毎月数百件の悪意パッケージを手動で削除している現状への改善期待が高い。

AI / 機械学習 / JAX / 教育リソース — 2026-11-15

DeepSeek V3を純粋なJAXで
約200行に凝縮した実装

研究者Vaibhaav Tiwariが、大規模言語モデル「DeepSeek V3」をGoogleのJAXライブラリで約200行に凝縮した実装をGitHubで公開した。119ポイント・7コメント。教育目的の超ミニマル実装で、MoE（Mixture of Experts）アーキテクチャの核心部分だけを抽出している。「LLMの内側を理解したい人」への入門コードとして評価されており、依存パッケージはJAXのみという潔い設計。
なぜこれが価値があるか
DeepSeek V3の公式実装はPyTorch+数万行のコードで、アーキテクチャを理解するには非常に複雑。この200行実装は本質的な部分（MoEルーティング・多頭注意・RoPE位置エンコーディング）だけを残しており、コードを読むことでアーキテクチャの核心が理解できる。NumPy経験者ならJAXの文法は比較的直感的に読める。
MoEとは何か
Mixture of Experts——複数の「専門家」ネットワークを持ち、入力に応じて適切な専門家だけを活性化する仕組み。全パラメータを使わないため、少ない計算量で大きなモデルと同等の性能を出せる。DeepSeek V3は671Bパラメータを持つが、推論時には37Bしか使わない。この実装でそのルーティング機構が200行で理解できる。

セキュリティ / 脆弱性開示 / Google / 業界標準 — 2026-11-15

Project Zero、報告から90日後に
脆弱性を開示するポリシーを明文化

GoogleのセキュリティリサーチチームProject Zeroが、脆弱性開示ポリシーを更新した。105ポイント・18コメント。ベンダーへの報告から90日後に脆弱性情報を公開するという方針を正式なポリシーとして文書化。パッチが出ていない場合でも90日経過後に開示するという姿勢を維持しており、「責任ある開示」の業界標準として長年機能してきた枠組みが改めて確立された。
なぜ90日という期限が重要か
脆弱性開示には永遠の課題がある：パッチが出る前に開示すると攻撃者に悪用される、しかしベンダーが「修正中」と言い続けて放置すれば何年もユーザーが危険にさらされる。90日は「ベンダーが本気で修正に取り組めば十分な期間」という経験値から来ており、Project Zeroの10年以上の活動で業界標準として定着。期限があることで企業のセキュリティ対応速度が実際に上がった。
今回の更新の要点
従来の実践を正式なポリシー文書として明文化し、例外規定（重大なインフラへの影響がある場合の延長手続き等）も整理した。HNコメント: 「Project Zeroは業界のセキュリティ文化を変えた。10年前には90日で開示するなんてありえないと言われていた」。現在はMicrosoftもAppleもこの期限を概ね尊重している。

AI / 開発ツール / ブラウザ自動化 / エージェント — 2026-11-15

Show HN: Agweb
——エージェントのための邪魔しないブラウザ

開発者paul_namelessが「Agweb」——AIエージェント向けに設計された軽量ブラウザ——をGitHubで公開した。79ポイント・21コメント。通常のブラウザと違い、エージェントがウェブを操作するために必要な機能だけを残してUIを極限までシンプルにした設計。ヘッドレスでもGUIでも動き、エージェントからツールとして呼び出しやすいAPIを提供。LLMを使ったウェブスクレイピング・調査フロー構築に活用できる。
Agwebが解決する問題
Playwrightや通常のChromedriverは人間向けに設計されており、エージェントが使うには過剰な機能と複雑なAPIがある。Agwebは「エージェントがウェブをナビゲートし、コンテンツを読み取り、フォームを操作する」という核心的なユースケースに特化。起動が速く、メモリ消費が少なく、エラーハンドリングがエージェントフローに適した設計になっている。
HNコメントと使い道
「Claude等のLLMと組み合わせてリサーチエージェントを作るのに良さそう」「Stagehandと比べてどうか」という技術的な質問が多い。作者は「Stagehandより軽量でシンプルなことが目標」と回答。MCPサーバーとの統合も検討中とのこと。AIエージェントがウェブを自律的に調査するユースケースへの関心の高まりを反映したプロジェクト。
