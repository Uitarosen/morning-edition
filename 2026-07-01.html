AI / CLAUDE CODE / セキュリティ / ANTHROPIC — Claude Codeがサーバーに送るリクエストにステガノグラフィー（隠し情報）を埋め込んでいることを研究者が発見。Anthropicが認め目的を説明。1190ポイント・310コメント

Claude Codeは
リクエストに
隠しマーキングを
埋め込んでいた

「Claude Code is steganographically marking requests（Claude Codeはリクエストにステガノグラフィーマーキングを行っている）」がthereallo.devで公開され、1190ポイント・310コメントという今日のHNで最大の話題となっています。研究者kirushikがClaude CodeのAPIトラフィックを詳細に分析したところ、Claude Codeがサーバーに送るプロンプトに通常では見えない形でマーキングデータが埋め込まれていることを発見しました。具体的には、ゼロ幅スペース（zero-width spaces）・特定のUnicode文字・ホワイトスペースパターンなどを使って、Claude Codeセッションを識別できるシグネチャが含まれているというものです。 発見後、AnthropicはこれがClaude Codeの意図的な設計であることを認め、その目的を説明しました。主な用途は①不正利用の検出（Claude Codeを名乗る偽クライアントや自動化スクリプトの識別）②モデルの自己認識の改善（自分がClaude Codeというコンテキストで動作していることをモデルが認識できるようにする）③フィードバックシステムの改善（どのリクエストがClaude Code経由かを追跡し、エージェント動作の品質改善に使う）——とされています。ただし、このマーキングがユーザーのコードやデータ自体に埋め込まれるわけではなく、Claude CodeがAPIに送るシステムプロンプトレベルの情報に限定されています。 HN上では「ステガノグラフィーという言葉の選択が問題——隠れてトラッキングしているように聞こえるが、実際はAPIプロンプトへのメタデータ付与」「プライバシーポリシーや利用規約にこれが明記されていなかったことが透明性の問題」「AIエージェントが自分自身のリクエストにサインを入れるのは実は理にかなっている——ループ検出・自己参照の回避に有効」「Cursor・Copilot等の他のAIコーディングツールも同様のことをしているのでは？調べてみる価値がある」「Anthropicがすぐに認めて説明したことは良かった——隠し続けることはできなかっただろう」という310コメントが展開中です。
ステガノグラフィーとは
情報を別の情報の中に隠す技術
暗号化（内容を読めなくする）とは異なり、情報が存在すること自体を隠す。今回はAPIプロンプト内のゼロ幅文字・Unicodeパターン等を使ってClaude Code固有のシグネチャを埋め込む。通常のユーザーには見えないが、ツールで分析すると検出できる
実際に影響があるか
ユーザーのコードやデータへの影響はなし
マーキングはClaude CodeがAnthropicのAPIに送るシステムプロンプトに含まれる。ユーザーが書いたコード・会話内容・出力結果には一切含まれない。Claude Code経由のAPI呼び出しを他と区別するためのメタデータ。プライバシーへの実害はほぼないが透明性の問題
Anthropicの説明
不正利用検出・モデル改善が目的
①偽Claude Codeクライアントや悪意ある自動化スクリプトの検出②Claude Codeコンテキストでの動作品質の追跡・改善③エージェントループ内での自己参照検出（Claude Codeが自分自身のAPIを呼び出す際に無限ループを防ぐ）に使用。発見後即座に認め説明した点は評価
今後への影響
AIツールの透明性議論が加速へ
この発見を受け、他のAIコーディングツール（Cursor・Copilot・Gemini CLI等）が同様のトラッキングを行っているかの調査が始まっている。「AIエージェントが送るリクエストに何が含まれるか」をユーザーが把握できる権利の議論へ。Anthropicはドキュメント更新を約束

ハードウェア / ドローン / DIY / エンジニアリング — ハードウェア経験ゼロの筆者が8プロペラのカスタムオクトコプターを独学で設計・製造。空力計算からPIDチューニングまでを詳細に記録。301ポイント・68コメント

ハードウェア
未経験から
8プロペラの
ドローンを作った

「Building a custom octocopter from scratch with no prior hardware experience（ハードウェア経験なしにカスタムオクトコプターをゼロから製作）」がKarolina Mgdubielによってkarolina.mgdubiel.comで公開され、301ポイント・68コメントを集めています。著者のKarolinaはソフトウェアエンジニアで、ハードウェアへのこだわりがゼロの状態から8プロペラのドローン（オクトコプター）を完全に独学で設計・製造するプロジェクトに挑みました。 ブログは製作の全過程を包み隠さず記録しています。最初の段階ではプロペラのサイズと回転数から揚力を計算する基本的な空力計算を理解することから始まり、次にフレームの選定と自作（カーボンファイバーチューブとアルミジョイント）、モーター・ESC（電子スピードコントローラー）・フライトコントローラー（Betaflight/ArduPilotベース）の選定と配線、そしてPID（比例-積分-微分）制御のチューニングまでを段階的にカバーしています。8プロペラ構成（オクトコプター）を選んだ理由は「1基のモーターが故障しても飛行継続できる冗長性」——カメラ撮影などのプロ用途での信頼性向上のため。特に印象的なのは「電気系統の問題で3度炎上させた」という失敗体験も包み隠さず記録している点で、リアルな学習の記録として高い評価を得ています。 HN上では「ソフトウェアエンジニアがハードウェアに踏み込む際の鉄板プロジェクト——失敗ありきの学習体験を正直に書いた点が素晴らしい」「PIDチューニングは本当に闇——Karolinaが苦労した様子が手に取るようにわかる。Autotune機能でも最終的には手動調整が必要」「ArduPilotよりBetaflightの方がホビー用途では簡単——FPVドローンの文化から入ると壁が低い」「オクトコプターはクアッドより高価だが冗長性の価値は本物——商業撮影では保険として使う価値がある」「次のステップはFPV（一人称視点）カメラとOSD（オンスクリーンディスプレイ）の追加——ぜひ続きを書いてほしい」という68コメントが展開中です。
オクトコプターとは
8つのプロペラを持つマルチコプタードローン。クアッドコプター（4プロペラ）が最も一般的だが、オクトコプターは①1基故障しても飛行継続可能（冗長性）②より大きなペイロード（カメラ・センサー）を運べる③振動特性が異なりカメラ映像がなめらか——という特性から、映像制作・測量・産業用途に使われる。コスト・重量が増すトレードオフあり
PIDチューニングとは
ドローンの安定飛行の心臓部。P（比例：傾きの大きさに応じた補正）・I（積分：持続する誤差への補正）・D（微分：変化の速さへの先読み補正）の3つのゲインを調整してドローンを滑らかに安定させる。値が高すぎると発振（ブルブル震える）、低すぎると鈍く不安定に。Autotune機能で自動設定できるが完全自動は難しく、最終的には手動での微調整が必要
ソフトウェアエンジニアがハードを学ぶ
Karolinaの事例が示す学習パス：①空力の基礎（揚力方程式）→②コンポーネント選定（モーター・ESC・バッテリー・フレーム）→③配線（半田付け・コネクター）→④フライトコントローラー設定（Betaflight/ArduPilot GUI）→⑤PIDチューニング（飛ばしながら調整）。ソフトウェアの「コンパイル・テスト・修正」サイクルと本質的に同じだが失敗が「炎上」として現れる

Neuralink：脳に直接電極を埋め込む（侵襲型）→高精度（ニューロン単位の信号）だが手術が必要。Brain2Qwerty：MEG/EEGで頭外部から計測（非侵襲型）→精度は低いが安全で繰り返し使用可能。医療分野では侵襲型が先行するが、日常的なBCIインターフェースとしては非侵襲型の方が普及の可能性が高い。MetaはMeta Glasses（ARメガネ）でのBCI入力に非侵襲型を目指していると見られる
プライバシーへの含意
現時点では①MEGは病院/研究室にしかない巨大装置②精度が低く実用レベルにない③被験者の協力が必要——のため実用的な脅威はない。しかし技術の方向性として：ウェアラブルEEGの精度向上＋AI技術の進歩が組み合わされば、将来的に「思考を読む」BCI端末のリスクが現実化する。Metaがこれを開発しオープンソース化することへの倫理的議論は始まっている
