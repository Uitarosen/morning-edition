SECURITY — Microsoftブラウザの深刻な設計上の欠陥

Microsoft Edgeが
全パスワードを平文で
メモリに保持していた

Microsoft Edgeの最新バージョンが、未使用状態でもパスワードマネージャーに保存した全パスワードをRAM上に平文（暗号化なし）で保持していることをセキュリティ研究者が発見し、HNで409ポイント・147コメントを集めています。Windowsのメモリダンプツールやプロセスインスペクタを使うと、Edgeを一切操作していない状態でもKeychain内の全パスワードを読み取れることが実証されました。競合のChrome・Firefoxでは同テストで平文パスワードは発見されず、Edge固有の実装問題であることが示されています。Windowsの「資格情報保護（Credential Guard）」が有効な環境でもEdgeのプロセスメモリには平文が残ることが確認されており、マルウェアがメモリスキャンで認証情報を一括窃取できる状態です。
問題の概要
平文パスワードがRAMに常駐
Edgeを開いているだけで全保存パスワードがメモリ上に暗号化なしで存在。プロセスダンプで一括取得可能
他ブラウザとの比較
ChromeとFirefoxは問題なし
同一テストでChrome・FirefoxはRAMに平文パスワードを残さないことを確認。Edge固有のアーキテクチャ上の問題
影響範囲
Edgeユーザー全員
Windows上でEdgeにパスワードを保存しているユーザーが対象。企業PCのコンプライアンスにも影響する可能性
今すぐできる対策
外部パスワードマネージャーへ移行
1Password・Bitwarden等に移行しEdge内蔵パスワード保存を停止。Microsoftの修正を待たずに実施すべき

PRIVACY — 医療申請データが広告目的で収集されていた

米医療保険サイトが
人種・市民権データを
MetaとGoogleに送信

TechCrunchとThe Markupが共同で実施した調査で、オバマケア（ACA）に基づく複数の州の医療保険マーケットプレイスが、ユーザーの市民権ステータス・人種・民族データをMeta（Facebook）とGoogleの広告追跡ピクセルで収集・送信していたことが判明し、HNで417ポイント・141コメントを集めています。ユーザーが「市民権の証明」「人種・民族」を申請フォームに入力するページでもFacebook PixelやGoogle Analyticsタグが動作しており、入力データがリアルタイムで広告大手のサーバーに転送されていました。HIPAA（医療情報保護法）が適用されないグレーゾーンを突いた実態であり、EFF（電子フロンティア財団）は「移民ステータスが広告データとして販売されていた可能性がある」と厳しく批判しています。
送信されていたデータ
市民権ステータス・人種・民族・入力したメールアドレス・居住州。申請フォームの入力内容がリアルタイムでMetaとGoogleに転送
追跡の仕組み
サイトに埋め込まれたFacebook Pixel・Google Analyticsタグが、URLパラメータとフォーム入力を自動収集。サイト運営者が意図せず設置していたケースも
法的グレーゾーン
HIPAAは医療機関・保険会社には適用されるが、保険マーケットプレイスのWebサイト自体には直接適用されないケースが多く、法的義務の空白が問題の温床
自衛策
医療系サイトへのアクセスはuBlock Origin等の広告ブロッカーを使用。Firefoxの強化型トラッキング防止機能も有効。VPNとプライベートブラウザの組み合わせを推奨

AI AGENTS × ARCHITECTURE — Claude Codeユーザー必読

エージェントスキル——
AIエージェントの
再利用可能な能力モジュール

GoogleエンジニアリングマネージャーのAddy Osmaniが「Agent Skills」の概念を解説したブログ記事がHNで109ポイント・33コメントを集めています。AIエージェントが汎用モデル1体ではなく「再利用可能な専門能力モジュール（スキル）」を組み合わせて動作するアーキテクチャパターンの詳細解説です。各スキルはコードレビュー・セキュリティ分析・DB最適化など特定ドメインに特化し、メインエージェントがタスクに応じて適切なスキルをオーケストレートします。Claude Code自身がこのアーキテクチャを採用しており、`~/.claude/agents/`のカスタムエージェント（planner・tdd-guide・code-reviewer等）がまさに「スキル」として機能しています。複数スキルの並列実行やパイプライン構築など、エージェント開発の実践パターンが豊富に紹介されています。
スキルとは
特定タスクに特化した再利用可能な能力モジュール。独立して機能するAIの専門ユニットで、組み合わせることで複雑なタスクに対応する
オーケストレーション
メインエージェントがタスクを分解し適切なスキルを選択・呼び出す。スキル間での情報受け渡しやパイプライン構築も可能。並列実行でスループット向上
Claude Codeとの関連
`~/.claude/agents/`のカスタムエージェントがこのパターンの実装。planner→tdd-guide→code-reviewerのチェーンがスキルパイプラインとして機能
設計の示唆
スキルを細粒度に分割するほど再利用性が上がる。「汎用エージェント1体」より「専門スキル10体のチーム」が複雑タスクに強い

DEV TOOLS — JSランタイム戦争の新局面

Bunが心配——
急成長ランタイムへの
エンジニアの懸念

「I am worried about Bun」というブログ記事がHNで408ポイント・279コメントの大規模議論を呼んでいます。JavaScriptランタイム「Bun」がNode.jsの代替として急速に普及する一方、著者はBunのアーキテクチャと開発体制に深刻な懸念を提示しています。主な問題提起は「Node.js互換性の主張が誇大で多くのパッケージが動かない」「ベンチマークが自社に有利な条件で計測されている」「oven社が小規模チームでランタイム・バンドラ・パッケージマネージャを同時開発しており持続可能性が疑わしい」の3点です。HNコメントでは実際にBunで本番移行を試みてハマった体験談が多数投稿されており、「Denoが経験したのと同じ課題だ」という指摘も目立ちます。
▸
互換性の問題: Node.js互換を謳うが、ネイティブモジュール（.nodeファイル）は非対応。npm パッケージの中にBun非対応のものが多数あり「移行してみたら動かなかった」という報告が続出している
▸
ベンチマーク疑惑: 公式パフォーマンス比較は「I/Oバウンドの単純タスク」が中心。CPUバウンド処理や複雑なアプリとの比較では差が縮まるという反論あり。計測条件の恣意性を指摘する声が多い
▸
持続可能性の懸念: ランタイム・テストフレームワーク・バンドラ・パッケージマネージャを少人数チームで全部作るのは過剰。各機能の完成度と長期メンテが不安という指摘が多数
▸
現在の妥当な評価: 新規プロジェクトでの採用は慎重に。Node.js/Denoの方が本番実績が豊富で、Bunは「有望だが未成熟」という評価が現場エンジニアの多数意見

DEV TOOLS — #4の懸念と重なる言語戦略の転換

BunがZigから
Rustへ移植中——
GitHubコミットで発覚

BunがZigで書かれた内部コードの一部をRustへ移植していることがGitHubのコミット履歴から発覚し、HNで64ポイント・27コメントを集めています。Bun開発元のoven社は「速さのためにZigを採用した」というブランドイメージを掲げてきましたが、ネットワーク・I/O等の特定モジュールでRustへの切り替えが確認されました。この発覚はストーリー#4「Bunへの懸念」と重なり、「言語選択も迷走している」という見方を強める一方、「Zigはまだ本番ランタイムには早い。Rustは安定した正しい選択だ」という擁護論も展開しています。Zigコミュニティにとっては、Zigの最大の本番採用事例の一つが実質的に撤退した形であり、失望の声が多数上がっています。
発覚の経緯
GitHubコミット `46d3bc29` でRustファイルが追加されていることをコミュニティが発見。公式アナウンスなし。Zigから段階的に移植している模様
移植の推定理由
「Zigのエコシステムが未成熟でライブラリが不足」「Rustの方がメモリ安全性ツールが充実」「Zigコンパイラの不安定さ」などが挙がる。公式コメントはまだない
Zigコミュニティの反応
BunはZigを本番スケールで採用した数少ない事例の一つだっただけに「痛い」という声が多い。Zigの実用的成熟度への疑問も再燃している
今後の見通し
完全なRust移植ではなく、問題のある部分だけRustに差し替えるハイブリッドアーキテクチャになる可能性。Bunのパフォーマンス特性への影響も注目される

AI INFRASTRUCTURE — リアルタイム音声AI配信のしくみ

OpenAIが低遅延音声AIを
スケールで提供する
仕組みを公開

OpenAIが「ChatGPT Voice」などのリアルタイム音声AIをどのようにスケールで低遅延提供しているかを技術ブログで解説し、HNで281ポイント・100コメントを集めています。ユーザーの発話からAI返答までの遅延を「知覚的に自然な会話」レベル（200〜300ms以下）に抑えるためのストリーミングアーキテクチャ・エッジキャッシング・GPUオーケストレーションの詳細が公開されました。特に「Speech-to-Speech」パイプライン（テキスト変換を挟まず音声を直接モデルに入力する方式）と、グローバル配信インフラの設計が技術的に読みごたえのある内容です。音声AI実装を検討するエンジニアにとって、インフラ設計の現実的な参照点となる稀少な公開情報です。
▸
レイテンシ目標: 200〜300ms以下を目標値に設計。人間の通常会話の応答時間（150〜300ms）に合わせることで「不自然な間」をなくし、自然な会話体験を実現
▸
Speech-to-Speechパイプライン: 音声→テキスト変換を省略し、音声波形を直接大規模モデルに入力する次世代アーキテクチャ。従来比で遅延を半分以下に削減
▸

▸
GPU動的割り当て: リアルタイム会話の断続的・バースト的なトラフィックパターンに対応した動的GPU割り当て。「使われていない時間が長い」音声の特性を活かしてコスト最適化

ビッグテックがユーザーを
望まない行動へ誘導することを
止めよ

エコノミスト誌の招待寄稿「Stop big tech from making users behave in ways they don't want to」が219ポイント・150コメントを集めています。ハーバード大学の経済学者が、SNSアルゴリズムが怒りを増幅するコンテンツを優先すること・通知設計がドーパミンを刺激すること・サブスクリプション解約をわざと複雑にするダークパターンを「ユーザーの意図に反する行動を引き起こす操作」として法的に規制すべきと論じています。EU DSA（デジタルサービス法）やFTCのダークパターン規制が前進例として引用され、「プラットフォームのデザインパターンを法的に規制する」アプローチの実現可能性が議論されています。HNでは「同意するが執行が難しい」「自由市場への介入だ」という賛否両論が展開されています。
代表的なダークパターン

SECURITY ENGINEERING — マルチテナント設計の落とし穴

国防省系スタートアップで
ゼロ認証脆弱性を
発見した全容

セキュリティ企業Strixが、米国防総省（DoD）のスタートアップが使うSaaSプラットフォームでゼロ認証（認証なし）でアクセスできるマルチテナント権限昇格脆弱性を発見した詳細レポートを公開し、HNで168ポイント・74コメントを集めています。複数の政府契約企業が共有するプラットフォームで、あるテナントのAPIが他テナントのデータを認証なしで読み書きできる状態になっていたという設計上の欠陥です。単純なリクエスト改ざん（テナントIDの数字を+1するだけ）で他社データにアクセスできることが確認されており、「責任ある開示」のプロセスが適切に行われた好例としても評価されています。マルチテナントSaaSの設計者必読の内容です。
▸
脆弱性の種類: IDOR（Insecure Direct Object Reference）。APIエンドポイントがリクエストのテナントIDを検証せず、任意のテナントのデータにアクセス可能な状態だった
▸
発見の経緯: Strixが自社の契約に関連するAPIを調査中に発見。テナントIDを+1するだけで別の政府契約企業のデータにフルアクセスできることを確認
▸
影響の深刻さ: 機密情報ではないが、契約内容・担当者情報・調達データなど競合他社に知られたくない情報が露出していた可能性。国防関連のためスコープは特に敏感
▸
修正と教訓: サーバーサイドで「リクエストのテナントIDと認証済みユーザーのテナントIDが一致するか」を全エンドポイントで検証する実装が必須。JWTクレームベース認可が有効な対策

WEIRD SCIENCE — 宇宙規模で重力法則を検証

ニュートンの重力法則が
史上最大スケールの
テストをパスした

ニュートンの万有引力の法則が「史上最大スケール」での検証テストに合格したとサイエンス誌が報告し、HNで137ポイント・128コメントを集めています。天文学者のチームが数千億個の星を含む銀河クラスター間の重力を精密に測定し、ニュートンの逆二乗則が数百万光年（メガパーセク）スケールでも成立することを確認しました。従来の実験室（数センチ〜数メートル）や太陽系（数AU）での検証と比べて6〜8桁大きいスケールの検証であり、「修正重力理論（MOND）」や「暗黒物質不要論」への強力な反証となっています。HNでは「ニュートンより一般相対性理論の検証だ」という注釈と「スケールフリーな法則の美しさ」への感嘆が入り混じった議論が展開されています。
テストのスケール
数百万光年（メガパーセク）スケールでの重力測定。太陽系スケールの検証と比べて6〜8桁大きい。宇宙で重力法則を検証した歴史上最大の試み
測定方法
銀河クラスターの空間分布と速度場から重力場を逆算。ジェームズ・ウェッブ宇宙望遠鏡の高精度観測データを使用して精度を確保
MOND理論への影響
暗黒物質の代わりに重力法則を修正する「MOND（Modified Newtonian Dynamics）」理論への打撃。MONDが予測する銀河スケールの重力と今回の結果が整合しない
暗黒物質との関連
ニュートン則が成立するためには「見えない質量（暗黒物質）が存在する」ことが前提となる。今回の結果は暗黒物質の存在を間接的に支持するものでもある
