Libghostty 1.0——
GhosttyのレンダリングエンジンがOSSライブラリに
——996pt

Mitchell Hashimoto（Vagrant・HashiCorp創設者）が個人プロジェクトとして開発するGPUアクセラレーテッドターミナルエミュレータ「Ghostty」のコアレンダリングエンジンが、`libghostty`としてv1.0ライブラリリリース。任意のアプリからGhosttyの高性能レンダリングをライブラリとして組み込めるようになりました。HNで996ポイント・174コメントを記録し、2026年11月8日の最高得票ストーリーです。
libghosttyとは何か——Ghosttyのアーキテクチャ
ターミナルエンジンを切り出したCライブラリ
Ghosttyの構造: 本体はZigで書かれたクロスプラットフォームターミナルエミュレータ。コアのVT100/xterm互換端末処理、Unicodeレイアウト、フォントラスタライズ、GPU描画パイプライン（Metal/Vulkan/OpenGL）を`libghostty`として分離。C ABIで公開: 純粋なCヘッダー（`ghostty.h`）を提供——C、C++、Python（ctypes）、Rust（bindgen）、Swift、任意の言語からFFIで使える。何ができるか: (1) 自分のアプリにGhosttyクオリティのターミナルウィジェットを埋め込む。(2) VSCode・JetBrains・Zedなど現状Electronベースのターミナルパネルを置き換え可能。(3) カスタムシェルホスト・TUIフレームワークの基盤として使える。ライセンス: MITライセンス——商用利用・改変・再配布自由。最初の採用例: 既にいくつかのIDEプラグインが`libghostty`への移行を表明している。
HNの174コメント——コミュニティの熱狂
「Electronターミナルが終わる日」論争
最高評価コメント: 「libghosttyのリリースは、各IDEがもう自分でターミナルエミュレータを実装しなくてよくなるという意味で歴史的——ちょうどWebKitがブラウザエンジンを民主化したように、libghosttyはターミナルを民主化する」。Zedチームの反応: 「Zedは既に独自のターミナル実装を持っているが、libghosttyのパフォーマンスベンチマークを見ると真剣に移行を検討せざるを得ない」というコメントが高評価。Electronターミナル批判: 「VSCodeのターミナルはWASMベースのxterm.jsで動いており、GPU描画に移行した版も出ているが、libghosttyと比較すると複雑さが桁違い——同じことをはるかにシンプルに実装できる」。日本のエンジニアのコメント: 「Ghosttyは日本語の等幅表示（全角文字）が最初からまともに扱えた唯一のターミナルだった——libghosttyがその能力を広く使えるようになるのは朗報」。パフォーマンス数値: リリースブログに記載の数値——xterm.jsの10〜30倍の描画速度（静的ベンチマーク）、メモリ使用量は約1/5。
Actionable——今すぐlibghosttyを試す
5行で動くターミナルウィジェット
インストール（macOS）: `brew install libghostty` → Homebrewで即時インストール可能。Rustから使う場合: `Cargo.toml` に `ghostty = "1.0"` を追加 → `use ghostty::Terminal;` → `Terminal::new().spawn("zsh")` で動く。Pythonから: `pip install ghostty-py` → ctypesラッパーが公開済み。最も実用的なユースケース: 自社の開発者向けWebアプリ（CI/CD管理画面・クラウドコンソール）にブラウザ内ターミナルを埋め込む際、xterm.jsの代替として評価する価値あり（WebAssemblyビルドも近日公開予定とのこと）。Claude Codeとの組み合わせ: Claude Code CLIはVT100互換端末で動作するため、libghosttyをホストとして使ったカスタムClaude Codeラッパー（独自UIでCLIをラップ）が作りやすくなる。リポジトリ: github.com/mitchellh/libghostty——Starは初日で8,000超。

Need for Speed
Underground 2
がブラウザで
フル動作——716pt

「nfsu2.xyz」がHNで716ポイント・206コメントを記録。2004年の伝説のレースゲーム「Need for Speed Underground 2」がWebAssembly移植によりブラウザ上でフルプレイ可能になりました。インストール不要、ロム合法問題をクリア済みのオープンソースポーティングが一夜にして話題をさらいました。
どうやってブラウザで動かしているか——技術スタック
移植の仕組み: オリジナルのNFSU2 PCバイナリをリバースエンジニアリングしてC/C++に再実装したオープンソースプロジェクト「re3/reVC」の系譜にある「NFSU2-reworked」を、Emscriptenを使ってWebAssemblyにクロスコンパイル。ゲームアセット: オリジナルのゲームアセット（テクスチャ・モデル・音楽）は含まれていない——プレイヤーが合法的に所有するゲームディスク（またはEA公式のアーカイブ版）からアセットをブラウザにロードする仕組みを取る。WebGL: レンダリングはWebGL2で処理——オリジナルのDirect3D 8コールをOpenGL ES 3.0互換の呼び出しに変換したラッパーを経由。音声: Web Audio APIでOGGフォーマットのBGMをストリーミング再生。コントローラー: Gamepad APIに対応——PS5/Xbox/ProコントローラーをUSBまたはBluetooth接続で即時認識。パフォーマンス: M2 Macのブラウザで常時60fps（Chromeで確認）、低スペックマシンでも30fps以上を維持。
HNの206コメント——ノスタルジアとオープンソースの勝利
感情的な反応: 「2004年の中学時代を過ごしたゲーム——ブラウザで動いているのを見て涙が出そうになった」というコメントが大量にアップヴォートされた。法的な考察: 「アセットを自分でロードする設計がポイント——コードを再実装してもゲームデータを含めるとDMCA問題になるが、ユーザー自身のアセットを使う設計にすることで大きなグレーゾーンを避けている」という法的解析コメント。EA公式の動き: 「EAがEA Mobiusでクラシックゲームのアーカイブ販売を始めているが、NFSU2は現時点でカタログ入りしていない——このプロジェクトがEAにプレッシャーをかける可能性がある」。技術的な賞賛: 「Emscriptenとbinaryen（WebAssembly最適化）の成熟度がここまで来たのかという驚き——5年前ならこの品質でブラウザ移植は無理だった」。オンラインモード: 「オリジナルのオンライン対戦は現在も実装中——2020年代のゲームインフラでNFSU2のオンラインを再現する試みは技術的に面白い」。
エンジニアとしての示唆——WebAssemblyの今の実力
この移植が示すもの: 2004年世代のゲームエンジン（Direct3D 8世代）のフル移植がブラウザで実用的に動く時代になった——WebAssembly + WebGL2 + WebAudioの組み合わせはゲームエンジン移植の実用ラインを超えている。ネイティブアプリのWeb移植を考えるとき: Emscriptenによる既存C/C++コードのWebAssembly変換は、UI部分（DOM操作が必要な部分）を除くコアロジックであれば驚くほど素直に動く。試してみる価値がある用途: (1) 既存のCLIツールをブラウザ上で動かす（例: ffmpegのWebAssembly版はすでに実運用されている）。(2) Python/Rubyインタープリタの埋め込み（教育・デモ用途）。(3) ゲームエンジン（Unity WebGL・Unreal→wasm）の組み込み。今すぐ遊ぶ: nfsu2.xyz にブラウザでアクセス → 自分のNFSU2ゲームファイルを指定 → プレイ開始。Chromeまたはエッジ推奨（Safariは一部WebGLエクステンションが未対応）。

Apple Intelligence / AI / macOS / 未公開機能 / プライバシー — 2026-11-08

すべてのMacに
「家族関係分類器」が
隠れている
——Apple知識グラフの実態——537pt

「Every Mac comes with an (undocumented) family member classifier」（8rank.ai）がHNで537ポイント・315コメントを集めています。Apple IntelligenceのPersonal Knowledge Graphがすべての対応Macに存在し、写真・メール・連絡先データからユーザーの家族関係を推論する隠し機能が発見されました。Appleのドキュメントには一切記載がないAIモデルの実在が確認されています。
何が発見されたか——Personal Knowledge Graphの正体
発見の経緯: 研究者がApple Intelligence関連のオンデバイスモデルバンドルを調査中に、`com.apple.intelligence.family-classifier`というバンドルIDを持つコアMLモデルを発見。モデルの機能: (1) 写真ライブラリのExif・顔認識データ・一緒に写っている頻度から「家族」「親戚」「友人」「職場」などの関係性をカテゴリ分類する。(2) メール・メッセージの送受信パターンと連絡先データを組み合わせて関係性グラフを構築する。(3) 「お父さん」「お母さん」「子ども」など具体的な続柄を推論するラベリングを行う。推論結果の用途: Siriが「お母さんに電話して」「子どもの誕生日を教えて」に正確に答えられるのはこのモデルがあるから。モデルのサイズ: 約38MB——完全にオンデバイスで動作、ネットワーク通信なし（プライバシー保護の観点）。対応デバイス: Apple Intelligence対応デバイス（M1以降のMac、A17/M系チップのiPhone・iPad）全てに含まれている。
HNの315コメント——プライバシー論争が勃発
最高評価コメント: 「Appleが『プライバシーがiPhoneです』と言い続けてきた文脈で、ユーザーの家族構成を自動的に推論するモデルが一切ドキュメント化されていないのは問題——オプトアウトができないのならEUのGDPR的に問題になりうる」。擁護意見: 「完全にオンデバイスで動いており、データがAppleサーバーに送られるわけではない——これはローカル処理のプライバシー保護の模範例では？」。反論: 「データがどこへ行くかではなく、ユーザーが知らないうちにシステムが自分の家族関係を推論・分類していること自体が問題——インフォームドコンセントの問題だ」。規制的視点: 「家族構成は特定個人の識別に繋がりうる機微情報——GDPR第9条のセンシティブデータカテゴリに近い性質がある」。技術者の評価: 「推論精度を実際にテストした人によると88〜92%の精度でカテゴリ分類できているとのこと——これは驚異的に高い。トレーニングデータが何だったのか気になる」。日本の法的観点: 「日本の個人情報保護法では家族構成は第三者提供に制限のある個人情報に当たる可能性がある」。
Actionable——自分のMacのPersonal Knowledge Graphを調べる
モデルの確認方法: ターミナルで `find /System/Library/AssetsV2 -name "*.mlpackage" 2>/dev/null | grep -i "family\|person\|contact"` を実行——インストール済みのMLモデルのリストが出てくる。Apple Intelligenceの無効化: 「システム設定 → Apple Intelligence & Siri → Apple Intelligence をオフ」——これでKnowledge Graphのインデックス生成も停止する（ただしモデルファイル自体は残る）。写真の顔認識との関係: 「写真 → 人物」機能をオフにすると家族分類モデルへの入力データが減る（完全には止まらない）。開発者向けの注目点: Core MLモデルのバンドルは`mlmodelc`形式で`coremltools`ライブラリで解析可能——`pip install coremltools` → `import coremltools as ct` → `model = ct.models.MLModel('/path/to/model.mlpackage')` → `print(model.input_description)`でモデルの入出力を確認できる。研究者の発見したモデルパスはブログポストに記載されている。

Asahi Linux / Apple Silicon / M-series / オープンソース / Linux — 2026-11-08

Asahi Linux
Progress Report 7.3——
M4 Pro/MaxもLinux化へ
——282pt

「Asahi Linux Progress Report 7.3」（asahilinux.org）がHNで282ポイント・231コメントを集めています。Apple Silicon向けLinuxディストリビューション「Asahi Linux」の最新進捗報告。M4 Pro・M4 MaxチップへのLinux対応が進み、GPU・NPU周りの重要なブレークスルーが報告されています。
Progress Report 7.3のハイライト——何が前進したか
M4 Pro/Maxサポート: M4 Proチップ搭載MacBook Pro（2024年後期モデル）でのLinuxブートが安定化。M4 Maxは実験的サポート段階に入った。GPU進捗（最重要）: Appleの独自GPU（AGX）向けオープンソースドライバー「Asahi GPU」がVulkan 1.3のConformanceを2026年10月に取得——これはApple SiliconでVulkan対応ゲームや一般的なLinux GPUアプリが動く土台が完成したことを意味する。NPU（Neural Engine）: M4系のANE（Apple Neural Engine）の一部機能がLinuxから使えるようになった——CoreML相当のモデル実行がオープンソースドライバー経由で可能になる見込み。Fedora Asahiの安定化: Fedora Linuxをベースにした推奨ディストリビューション「Fedora Asahi Remix」がM4 Proまで動作確認済みに。Bluetooth: 一部モデルでBluetooth 5.3が安定化し、ヘッドフォン・コントローラーが使えるように。残課題: Thunderboltポート完全対応・動的周波数スケーリングの精度向上・スリープからの復帰安定性。
HNの231コメント——「なぜApple Siliconでわざわざ」論争
「なぜMacでLinuxを動かすのか」への答え: (1) Apple Siliconのコストパフォーマンスがx86の同価格帯デスクトップを明らかに上回る——Linuxでも同じハードを使いたい需要は実在する。(2) 企業や研究機関でmacOSではなくLinuxが必須の環境（特定のカーネルモジュール・特定のglibcバージョン依存）がある。(3) パワーユーザーがmacOS環境を維持しながらデュアルブートでLinux開発環境を持ちたい。Vulkan Conformanceの意義: 「AGXがVulkan 1.3に合格したことは、Apple Siliconが公式にゲーム開発者向けGPUとして使えるターゲットになることを意味する——Proton（Steam Play）経由でWindowsゲームが動く可能性が一気に近づいた」。開発チームへの敬意: 「Aspire Linuxチームは報酬なしで、Appleが一切ドキュメント公開しない独自ハードウェアを完全にリバースエンジニアリングしている——Linuxカーネルコミュニティ最大の快挙の一つ」。日本語入力: 「Asahi LinuxでFcitx5+Mozcが動くようになって日本語入力も問題なくなった——日本語環境でも十分実用的になってきた」。
Actionable——2026年にAsahi Linuxを試す手順
対応モデル確認: asahilinux.org/supported-hardware でM1〜M4対応状況を確認。M1/M2/M3系は安定版、M4はベータ段階。インストール方法: macOSターミナルで `curl https://alx.sh | sh` → インタラクティブなインストーラーが起動 → パーティション分割してデュアルブート構成を作る（macOSは消えない）。最小ディスク空き容量: 60GB以上推奨。推奨ディストリ: Fedora Asahi Remix（`fedora-asahi-remix.org`）——最も安定していてデスクトップ用途に最適。開発者向けユースケース: (1) Dockerコンテナのaarch64ネイティブ実行（Rosetta不要で高速）。(2) クロスコンパイル環境の構築。(3) AIモデルのオープンソースGPUドライバー実験環境。試す前の注意: 内蔵SSDへの直接インストールのため、必ずmacOSでTimeMachineバックアップを取ること。

AI Frontiersとは何だったか——解散の背景
グループの歴史: Microsoft Research内のAI Frontiersは、強化学習・機械学習基礎理論・因果推論・自然言語処理の基礎研究を行う精鋭チームとして2010年代に設立された。著名な成果: (1) Vowpal Wabbit（高速オンライン学習ライブラリ）——現在もML業界で広く使われている。(2) 文脈バンディット問題の実践的アルゴリズム——推薦システムの基礎理論に影響。(3) Decision Serviceフレームワーク——実運用可能な強化学習システムの先駆け。解散の経緯（Langford氏ブログより）: Microsoftの全社的なAI戦略がOpenAIとのパートナーシップ（GPT-4系モデルの応用）に集中シフトする中で、基礎研究への投資優先度が大幅に低下。グループメンバーの行方: 一部はMicrosoft内の応用AI部門へ異動、一部は学術界・他社（Anthropic・Google DeepMind・Meta AI等）へ転職。MicrosoftのAI研究への影響: 基礎研究よりも製品統合（Copilot・Azure AI）への集中が一層加速する見通し。
HNの154コメント——「基礎研究のホームはどこへ」

エンジニアとしての受け止め方——中長期への示唆
何を意味するか: (1) 次のブレークスルーがどこから来るかが不透明になった——ビッグテックの基礎研究が縮小するなら、次の変革はスタートアップか学術界から来る可能性が高い。(2) VW（Vowpal Wabbit）のような実用的な基礎研究ツールが供給される場が減る——OSSコミュニティへの影響。(3) 強化学習・因果推論の基礎研究が手薄になる可能性——AGI競争がトランスフォーマースケーリングに偏りすぎる懸念。エンジニアとして注目すべき動き: AI Frontiersを離れた研究者の行き先が今後のAI研究の重要ハブを示す——特に「因果推論×LLM」「オンライン学習×大規模モデル」の融合研究が進む組織に注目。Anthropic・DeepMind・学術界への採用枠拡大は関連ポジションを探すチャンスかもしれない。John Langford氏の今後: ブログでは次の行き先は明かしていないが、彼のツイートを追うと動向がわかる（@acm_science）。
