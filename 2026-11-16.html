Claude Code / AI開発ツール / リバースエンジニアリング / 組み込み — 2026-11-16

Claude CodeとCodexが
$3 Arduinoで30年前のジープのECUを解読

開発者がClaude Code（Anthropicのコーディングアシスタント）とOpenAI Codexを使い、わずか3ドルのArduinoで1994年製ジープ・チェロキーのエンジン制御ユニット（ECU）をリバースエンジニアリングした動画がYouTubeで公開された。269ポイント・137コメントを獲得。OBD-II以前の独自シリアルプロトコルを生の16進数ダンプからAIが逆算し、走行データのリアルタイム取得に成功。「AIを使えばハードウェアの深い部分まで誰でも触れる時代が来た」と話題を呼んでいる。
何をしたか
30年前の独自ECUプロトコルをAIで解析
1994年製ジープのECUはOBD-II非対応で独自のシリアル通信を使っている。Arduinoでバスをスニッフィングし、取得した16進ダンプをClaude CodeとCodexに渡すことでプロトコル仕様を逆算。エンジン回転数・水温・燃料噴射量をリアルタイム表示することに成功した。
Claude Codeの役割
パターン認識とデコードコードの自動生成
生の16進ダンプを渡すとバイト列のパターンを推定し、Pythonのデコードスクリプトを即座に生成。「チェックサムはここにあるのでは」「フレーム開始は0xFEでは」という仮説を立てながら実装を繰り返す様子が「ペアプログラミングそのもの」と好評。
HNコメントの洞察
「AIがハードウェアの壁を下げた最良の例」
「これまでECUの解析は専門知識が必要で敷居が高かった。AIがあれば素人でもプロトコルを解析できる時代になった」という意見が多数。「次は燃料マップのチューニングまでできるのでは」という期待コメントも。コストが$3というのが特に注目された。

宇宙 / SpaceX / 再利用ロケット / エンジニアリング — 2026-11-16

SpaceX、Starship 15号機で
Mechazillaキャッチを再び達成

SpaceXのStarship第15回飛行試験が完了し、スーパーヘビーブースターが発射台「Mechazilla」の機械アームにキャッチされた。1613ポイント・1185コメントで今日のHN断トツのトップ。Flight 14に続く2回連続キャッチ成功。上段Starship本体の大気圏再突入と太平洋への精度着水にも成功しており、完全再利用ロケットシステムの実現へ着実に前進した。
2回連続キャッチが意味すること
1回成功は偶然の可能性があるが、2回連続は再現性を示す。ブースターキャッチが安定すれば着地脚を廃止できる——重量削減→ペイロード増加→打ち上げコスト低減というサイクルが実現する。SpaceXは次のマイルストーンとしてStarship本体（上段）のMechazillaキャッチを目指している。両段ともキャッチできれば完全再利用ロケットの完成。
NASAのアルテミス計画への影響
StarhipはNASAが次の月面着陸ミッション（アルテミス3号）の月面着陸機として採用している。開発が遅れると月面着陸ミッションにも影響するため、2回連続成功はNASAにとっても朗報。SpaceXは2027年の月面着陸を目指しており、今年中にStarship本体のキャッチを実現したい考え。
HNコメントの注目ポイント
「再飛行ターンアラウンドタイムは何日か」という質問が多い——SpaceXは数週間でブースターを再使用できると主張しているが、まだ実証されていない。「本当の意味でのゲームチェンジャーはブースターをその日のうちに再使用できるようになった時だ」という洞察が上位コメントに。ロケットの完全再利用は航空機並みのターンアラウンドが最終目標。

AIが生成したコードは
すべてオープンソースにすべきか

プログラマーJakub Jankiewiczが「AIが生成したコードはすべてオープンソースライセンスで公開すべきだ」という主張を発表し、993ポイント・550コメントと今日2番目の注目度を集めた。AIはオープンソースコードで訓練されており、AI生成コードをプロプライエタリにするのは倫理的に問題があるという論理。HNでは賛否両論の激しい議論が展開されている。
著者の主張の核心
① AIはオープンソースコードで訓練された（GitHubのパブリックリポジトリ等）② その知識を使って生成されたコードは「オープンソースの蒸留物」③ だから生成コードはオープンソースライセンスで公開すべき——という3段論法。さらに「AIが介在した時点でそのコードに真の著作権者は存在しない」という法的な議論も展開している。
HNの主要な反論
「訓練データの出所と生成物の権利は別問題」「これを言い出すと人間が学習した全てのコードもOSSにしなければならない」「企業の機密ロジックをAIに渡したくなくなるのでは」という反論が多数。法的観点から「現行著作権法はAI生成物の権利主体を想定していない」という指摘も。賛成派は「そもそもAI生成コードに著作権は発生しない」と主張している。
実務への影響
この議論は企業のAI利用規約にも関連する。GitHub Copilotの利用規約では「生成物の著作権はユーザーに帰属するが、類似コードの生成リスクはユーザーが負う」とされている。現状は法的グレーゾーンで、各国で訴訟が起きている。日本でもAI生成物の著作権帰属が議論になっており、HNコメントでは「日本の著作権法はAI生成物をどう扱うか」という質問への回答が注目された。

半導体 / 独禁法 / 価格操作 / Samsung / SK Hynix / Micron — 2026-11-16

Samsung・SK Hynix・Micronの
DRAM価格カルテル訴訟が存続

Samsung・SK Hynix・Micronの3社によるDRAM価格操作の共謀を主張する集団訴訟で、裁判所が被告3社の訴訟棄却申立を否認した。479ポイント・210コメント。DRAM市場は実質3社寡占であり、価格協調の疑惑は以前からあった。今後の証拠開示（discovery）フェーズに進むことで、価格操作の実態が明らかになる可能性がある。
この訴訟の背景
世界のDRAM市場はSamsung・SK Hynix・Micronの3社で約95%を占める極端な寡占状態。2016〜2017年にかけてDRAM価格が急騰した際に「3社が協調して意図的に供給を絞り価格を吊り上げた」とする集団訴訟が起きた。訴状では「競合他社への情報提供、価格・生産量の協調が行われた」と主張している。今回、裁判所が「訴訟を棄却するには証拠が不十分」として存続を認めた。
HNコメントの洞察
「DRAM市場の寡占がここまで進んだのは業界再編と価格競争の結果——悪意ある共謀なのか、それとも自然な市場収束なのか」という議論が活発。「価格協調の証拠を見つけるのは難しい。メールや会議録でも残っていない限り」という懐疑論も。「2016年のDRAM価格急騰でサーバー調達コストが2倍になった企業が多かった」という被害の実態報告も。
業界への示唆
この訴訟の帰結はDRAM・NAND市場の規制論議にも影響する。もし価格協調が認定されれば、半導体への独禁法適用が強化される可能性がある。長期的には新興プレイヤー（中国CXMT等）の台頭が寡占緩和につながるかもしれないが、先端DRAM製造の技術的障壁は依然高い。日本はDRAM調達コストに直接影響を受けるため注目すべき裁判。

ハードウェア / Apple / MacBook / ディスプレイ / 健康 — 2026-11-16

MacBook ProのOLEDディスプレイは
「より良い」どころか目に悪い可能性

macAnorakがMacBook ProのOLEDディスプレイに深刻なPWM（パルス幅変調）ちらつき問題があると報告した。371ポイント・198コメント。OLEDは有機EL発光のため目に優しいと思われがちだが、低輝度時に高頻度のPWMちらつきが発生しており、頭痛・眼精疲労の原因になる可能性が指摘されている。LCDからOLEDへの移行が「アップグレード」どころか一部ユーザーに悪影響をもたらす可能性がある。
PWMとは何か、なぜ問題か
PWM（パルス幅変調）はディスプレイの輝度を高速オン/オフで制御する技術。200Hz以上の高周波ならほとんど問題ないが、低周波（60〜120Hz程度）だと目に見えないちらつきが発生し、眼精疲労・頭痛・偏頭痛を引き起こす人がいる。LCDはバックライトでPWMを使うが、OLEDは各画素が自発光するため低輝度時のPWM制御が難しくなる。MacBook ProのOLEDは低輝度設定時にPWM周波数が低下するとされる。
誰が影響を受けるか
PWM感受性は個人差が大きく、全員に問題が起きるわけではない。しかし「OLED MacBook Proに替えてから頭痛が起きるようになった」という報告が多数寄せられており、HNスレッドでも「返品した」というコメントが複数。開発者・デザイナーなど長時間ディスプレイを見る職業の人に特に影響が出やすい。DC調光（PWMを使わない輝度制御）を採用していないディスプレイは今後も問題になりうる。
解決策と代替選択肢
① 輝度を高めに設定する（低輝度ほどPWM周波数が下がる）② 外付けのDC調光対応モニターを使う。HNコメントでは「ThinkPadのIPSパネルに戻した」「外付けMiniLEDモニターのほうがマシ」という意見も。AppleがDC調光対応OLEDを採用するまでは、PWM敏感な人にとってMacBook Pro OLEDは避けるべき選択肢かもしれない。

クラウド障害 / Microsoft / セキュリティ / 物理的影響 — 2026-11-16

Microsoft 365の障害が
塩素ガス漏洩・15名中毒の引き金に

ドイツのWDRが報じたところによると、Microsoft 365のクラウド障害が原因でドイツの遊園地「ファンタジーランド」の水処理システムが誤動作し、塩素ガスが漏洩して宿泊客15名が中毒症状を起こした。253ポイント・126コメント。クラウドサービスの障害が物理的な安全問題に直結するという事例として大きな注目を集めている。
何が起きたか
Microsoft 365の障害により、水処理システムの制御ソフトウェアが正常に動作しなくなった。塩素注入量の制御が失われ、プールや宿泊施設の水に過剰な塩素が混入した。宿泊客15名が目・呼吸器への刺激症状を訴え病院に搬送された。重症者はいなかったとされるが、クラウド依存の制御システムのリスクを改めて示した。
なぜこれが重大なのか
水処理・電力・交通制御といった重要インフラが、パブリッククラウドの可用性に依存するようになっているという問題の具体例。「SaaSで動く安全クリティカルシステムはアーキテクチャの失敗だ」というHNコメントが多数。フェイルセーフ設計（障害時に安全な状態に戻る設計）があれば防げた可能性がある。クラウドへの過度な依存を見直す議論が活発化している。
業界への示唆
「OT（運用技術）とIT（情報技術）の融合が進むほど、このような事例は増える」というHNコメントが支持を集めた。産業制御システム（ICS/SCADA）をクラウド接続する際のリスク管理が問われている。日本でも水道・電力の制御システムのクラウド移行が進んでいるが、このような事例は設計基準の見直しを促す可能性がある。フォールバック機能の必須化を求める声も。

宇宙 / NASA / 歴史 / 変わった雑学 — 2026-11-16

アポロ宇宙船はなぜ
グレネードランチャーを搭載していたのか

Space.StackExchangeに2019年に投稿された「アポロ宇宙船がグレネードランチャーを搭載していた理由」という質問への回答が208ポイント・140コメントを集めてHNで大きく話題になった。実際には打ち上げ花火のような信号弾発射装置で、着水後に遭難した場合に地上救助隊に位置を知らせるためのもの。しかしその背景には当時の冷戦下での設計思想が反映されており、興味深い歴史的文脈がある。
「グレネードランチャー」の正体
アポロ宇宙船に搭載されていたのは「Mk 13 Mod 0 Marine Signal Flare」——軍用の信号弾発射装置。着水後に宇宙飛行士が遭難した場合に空から発見されやすくするためのものだった。ただし設計は実際のグレネードランチャーに基づいており、パーツも軍用規格のものが流用されている。これがHNで「アポロにグレネードランチャーがあった」という驚きをもって語られた。
なぜ軍用装備が宇宙船に
アポロ計画の宇宙飛行士はほぼ全員が軍パイロット出身で、射出座席・救命装備・通信機器など多くが軍規格だった。着水後の救助シナリオでは「太平洋の広大な海上で宇宙船が発見されない」という最悪ケースを想定した装備が必要で、信号弾は最も確実な手段の一つだった。現代のGPS・衛星通信がなかった時代の設計思想を反映している。

AI / 機械学習 / LLM / 教育 — 2026-11-16

現代LLMの位置エンコーディングを
完全に理解する

ML研究者Sebastian Raschkaが現代LLMの位置エンコーディング（Positional Embeddings）を体系的に解説した記事を公開した。180ポイント・22コメント。RoPE・ALiBi・YARN・LongRoPEなど、主要LLMが採用する位置エンコーディング手法の違いと特性を丁寧に説明しており、「これほど整理された解説は珍しい」と高く評価されている。LLMの内側を理解したい開発者・研究者に必読の内容。
なぜ位置エンコーディングが重要か
TransformerベースのLLMは基本的にはテキストをトークンの「袋」として処理する——つまり語順の情報が失われる。これを補うのが位置エンコーディング。どのトークンが何番目にあるかをモデルに伝える仕組みで、長文理解・コードの順序依存ロジック・長期文脈保持の性能に直結する。RoPE（Rotary PE）はGPT-4・LlamaやClaudeが採用し、長文対応に優れている。
各手法の特徴（要点）
① Sinusoidal PE（初代Transformer）：シンプルだが長文で劣化。② ALiBi：訓練長を超えたコンテキスト外挿が得意。③ RoPE：相対位置情報をQ/Kベクトルに組み込む——現在の標準。④ YARN：RoPEを長文に拡張、コンテキスト窓を後付けで伸ばせる。⑤ LongRoPE：さらに最適化してより長い文脈を安定して処理。Claude・GPT-4oが長文対応できるのはこれらのおかげ。

神経科学 / 動物行動学 / 変わった科学 — 2026-11-16

「鳥頭」は誤解だった——
カラスの意思決定は人間より速い

New York Timesが報じた最新研究によると、カラスは人間よりも速く複雑な意思決定ができることが判明した。107ポイント・82コメント。鳥の脳は哺乳類の大脳皮質とは全く異なる構造を持つが、機能的には同等かそれ以上の高次認知処理が可能であることが示された。「birdbrain（鳥頭）＝頭が悪い」という英語の慣用表現はいよいよ死語になりそうだ。
研究の内容
研究者たちはカラスに対して「二択の意思決定課題」を与えた。片方の選択肢に報酬が隠れており、カラスはどちらを選ぶか決定しなければならない。結果：カラスの決定時間は人間よりも一貫して速く、かつ精度も同等かそれ以上だった。さらにカラスは「不確実性を認識し、わからない時には選択を保留する」という高度なメタ認知能力も示した——これは従来、人間や類人猿にしかないとされていた能力。
なぜ鳥の脳は「小さいのに賢い」のか
鳥の脳は哺乳類と異なり「大脳新皮質」を持たない。しかし「外套（Pallium）」と呼ばれる構造が類似した機能を果たすことが判明している。ニューロンの密度が哺乳類より高く、小さい体積でも膨大な計算が可能。「脳の構造が違っても知性は発達できる」という示唆は、AIアーキテクチャの多様性にも示唆を与えるとHNコメントで議論された。

AIセキュリティ / エージェント / プロンプトインジェクション — 2026-11-16

AIエージェントは知らずのうちに
「ハック可能なもの」を選んでいる

セキュリティ研究者Geoff Stearnsが「AIエージェントは複数の選択肢から無意識にハック可能なものを選びやすい」という問題を指摘した記事を公開した。38ポイント・15コメント。エージェントがウェブ検索や外部ツールを呼び出す際、悪意あるコンテンツでプロンプトインジェクションされたページが優先的に返されるよう細工されていれば、エージェントは知らずにそれを選択する可能性がある。AIエージェントのセキュリティ設計において重要な視点を提供している。
具体的な攻撃シナリオ
① ユーザーがエージェントに「最良のpythonライブラリを探してインストールして」と依頼。② エージェントがウェブ検索を実行。③ 悪意ある攻撃者が検索結果の上位に「見た目は正常だが、裏に隠れたプロンプトインジェクション指示が書かれた」ページを置く。④ エージェントがそのページを「優れたライブラリの推薦」として解釈し、マルウェアをインストールする指示に従ってしまう。これはAIエージェントへのサプライチェーン攻撃の一形態。
対策と今後の課題
「エージェントが読んだコンテンツは信頼してはならない——コンテンツは常にデータとして扱い、指示として解釈しない」という原則が重要。しかしLLMベースのエージェントはテキストをデータと指示の両方として同時に処理するため、根本的な対策は難しい。サンドボックス化・権限最小化・人間の承認ステップの挿入が現実的な対策。Claude等のAIはこの問題を認識しており、「観察したコンテンツは命令として扱わない」というガードレールを実装している。
